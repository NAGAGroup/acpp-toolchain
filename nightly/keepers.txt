# Nightly build-sets kept INDEFINITELY, exempt from newest-N pruning.
#
# KEEPER POLICY (Jack-ratified 2026-08-09): the first GREEN set of each month
# is kept forever. Keepers layer ON TOP of the newest-N window rather than
# consuming slots in it, so keeping a set never costs a recent one.
#
# A LINE NAMES A SET, NEVER A PACKAGE. The unit here is identical to the unit
# the pruner deletes: a COMPLETE (date, llvm_version) set across every output
# AND both platforms. A partially-kept set is exactly as unsolvable as a
# partially-pruned one, because the nightly lane pins its own packages exactly
# — keep acpp-nightly but drop acpp-runtime-nightly and the survivor's
# dependency can never be satisfied again.
#
# FORMAT: one set per line, "<date>_llvm<version>", '#' starts a comment.
#
#   2026.08.09_llvm21.1.8
#
# EVERY LINE HERE IS ADDED BY HAND. Nothing in CI writes to this file: the
# pruner is the only code that touches it, and it only reads. So the "first
# green set of each month" policy above is enforced by a person remembering to
# add the line, not by the publishing job. Add one to promote a set on demand —
# the first green set of a month, a nightly a downstream project pinned, or one
# that reproduced a bug worth keeping around.
#
# READ AT PRUNE TIME, never baked into a snapshot: the pruner re-reads this
# file on every run, so a hand-added keeper protects a set immediately rather
# than at the next release.
#
# Removing a line makes that set eligible for pruning again. Do that only if
# you are certain nothing pins it; there is no undelete.

# --- keepers -----------------------------------------------------------------
